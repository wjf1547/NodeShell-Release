# 第 1 章 · 快速开始

## 1.1 nsapp 是什么

nsapp = **一个 zip 包**，里面装着一个 Node.js 小程序。基座 APK 内嵌 Node.js v18 运行时，
把它解压到本地、跑起 `main.js`，你的应用就跑起来了。

```
你写的代码 (main.js)  ──▶  Node.js 运行时 (基座内嵌)  ──▶  JSON-RPC  ──▶  原生 UI 渲染
   你的全部逻辑             $ui/$http/$media...               render 事件     列表/图片/播放器
```

关键事实，先建立正确预期：

| 事实 | 含义 |
|---|---|
| **加密/解析 100% 在你的 JS 里** | 基座只负责「播放 URL」「渲染控件」，不做任何业务逻辑 |
| **基座一旦发布就不变** | 新功能 = 推新应用，不需要改基座、不需要重新打包 APK |
| **应用 = 标准 Node.js 程序** | `http/https/fs/crypto/stream` 全都能用，能 `require` npm 包 |
| **每个应用独立运行** | 独立 vm 上下文 + 独立数据目录 `<appData>/<id>/`，互不干扰 |

## 1.2 环境要求

**写应用只需要一个文本编辑器**，不需要 Android Studio、不需要 JDK。

| 用途 | 需要什么 |
|---|---|
| 只写应用（改 main.js） | 任意编辑器 + Node.js 18+（本地语法检查用） |
| 打包成 .nsapp | Node.js + `zip` 命令 |
| 改基座本身 | JDK 21 + Android SDK + Gradle（一般用不到） |

本地有 Node 就能做语法检查：

```bash
node --check apps/my-app/main.js     # 语法检查，不执行
```

## 1.3 五分钟跑通第一个应用

### 步骤 1：建目录

```bash
cd <仓库根目录>/apps
mkdir -p my-app/assets
```

### 步骤 2：写 package.json

```bash
cat > my-app/package.json <<'EOF'
{
  "id": "my-app",
  "name": "我的第一个应用",
  "version": "1.0.0",
  "main": "main.js",
  "icon": "assets/icon.png",
  "description": "Hello NodeShell",
  "apiVersion": 1
}
EOF
```

### 步骤 3：写 main.js

```bash
cat > my-app/main.js <<'EOF'
// 我的第一个 nsapp
$app.on('launch', () => {
  $ui.render({
    type: 'root',
    props: { title: '我的应用' },
    children: [
      { type: 'text', props: { text: 'Hello NodeShell!', size: 18, bold: true } },
      { type: 'button', id: 'btn', props: { text: '点我', onClick: 'hello' } },
    ],
  });
});

$ui.on('hello', () => {
  $app.toast('你点击了按钮 🎉');
});
EOF
```

### 步骤 4：放一张图标

**每个应用必须有 `assets/icon.png`，且必须是正方形**（推荐 256×256）。
基座自带的批量生成脚本（纯 stdlib，无需 PIL）：

```bash
python3 server/make_app_icons.py my-app
```

### 步骤 5：打包

```bash
cd <仓库根目录>/server
node pack.js
# → data/apps/my-app.nsapp + 写入 data/built.json
```

### 步骤 6：起商店服务端

```bash
cd <仓库根目录>/server
node server.js          # 默认 0.0.0.0:8788 (可用 PORT/HOST 覆盖)
```

### 步骤 7：手机上装

1. 手机与电脑连**同一 Wi-Fi**
2. 基座 → 设置 → 应用商店 → 地址填 `http://<服务器地址>`
3. 商店页点「刷新」→ 找到「我的第一个应用」→ 点安装
4. 回启动器，图标出现了，点开

> 也可以用文件方式安装：把 `my-app.nsapp` 传到手机，点一下 → 弹确认框 → 装。
> 第三种方式是链接：`nodeshell://install?url=http://<服务器地址>/apps/my-app.nsapp`

## 1.4 应用目录结构

```
apps/my-app/
├── package.json      # 必填：应用清单
├── main.js           # 必填：入口文件（package.json 的 main 字段指定）
├── assets/           # 图标与资源
│   └── icon.png      # 必填，正方形，推荐 256×256
└── node_modules/     # 可选：自带 npm 依赖，require 时从应用目录解析
```

### package.json 字段说明

```json
{
  "id": "my-app",                    // 必填，全局唯一，小写连字符，无任何回退
  "name": "我的第一个应用",           // 显示名
  "displayName": "我的第一个应用",    // 可选，长名
  "version": "1.0.0",                // 版本号，商店据此判断能否升级
  "main": "main.js",                 // 必填，入口文件
  "icon": "assets/icon.png",         // 图标路径（相对应用根）
  "description": "Hello NodeShell",  // 商店列表描述
  "apiVersion": 1,                   // 应用要求的协议版本，基座过低会拒绝运行
  "prefs": {}                        // 可选，v1 仅作元数据；实际读写用 $prefs
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 全局唯一。基座用它建数据目录、判断「是否已安装」。**改了 id 等于新应用** |
| `main` | ✅ | 入口文件，相对应用根 |
| `name` | ✅ | 商店与启动器显示名 |
| `version` | 建议 | 升级时必须比旧版本大（字符串比较） |
| `icon` | ✅ | 打包脚本会强制校验存在 |
| `apiVersion` | 建议 | 当前 = 1。基座版本低于它 → 拒绝运行并提示升级 |
| `description` | 建议 | 商店列表显示 |

## 1.5 应用生命周期

```js
$app.on('launch', () => { /* 应用启动时调用一次，这里做首屏渲染 */ });
$app.on('resume', () => { /* 从后台回前台 */ });
$app.on('pause',  () => { /* 切到后台 */ });
$app.on('back',   () => { /* 基座已 pop UI 栈后通知，只同步业务状态 */ });
$app.on('destroy',() => { /* 应用被卸载前，清理定时器 */ });
```

最小骨架：

```js
$app.on('launch', () => {
  $ui.render({
    type: 'root',
    props: { title: $app.name },   // $app.name 来自 package.json
    children: [ /* ... */ ],
  });
});
```

## 1.6 全局 API 一览（先混个眼熟）

```js
$app      应用生命周期与元信息        $app.on / $app.toast / $app.exit / $app.share ...
$ui       界面渲染与交互              $ui.render / $ui.push / $ui.pop / $ui.on / $ui.alert ...
$media    内嵌迷你播放器              $media.open({url, type, title, autoPlay})
$http     HTTP 请求（永远直连）       $http.get / $http.post / $http.request / put / del / head
$mhttp    出口代理版 HTTP             $mhttp.get / $mhttp.url / $mhttp.ready
$storage  键值存储                    $storage.get / set / remove
$prefs    用户配置存储                $prefs.get / set   （prefs. 前缀落盘 prefs.json）
$webview  全屏网页                    $webview.open({url, title})
$ssh      原生 SSH 终端               $ssh.open({host, port, user, ...})
$termux   本地 shell 终端             $termux.open({cwd, shell, commands})
$wifi     扫描附近热点                $wifi.scan()
$shell    基座信息                    $shell.version / $shell.apiVersion / $shell.server ...
CFG       出口代理全局配置（只读）    CFG.ip / CFG.port / CFG.freeHost / CFG.enabled
$toast    轻提示                      $toast(msg)，同 $app.toast
```

完整签名与坑见 [第 11 章](11-JS-API-详解.md)。

## 1.7 三个必懂的机制（先知道，后面细讲）

**① 界面是一棵「树」，每次变化整棵重新描述。**

```js
// 不是「把第 3 个按钮的文字改掉」，而是「重新描述整棵树」
$ui.render({ type:'root', props:{title:'X'}, children:[ /* 完整描述 */ ] });
```

**② 事件用字符串名注册，不用闭包。**

```js
// 节点上挂事件名（字符串）
{ type: 'button', props: { text: '点我', onClick: 'hello' } }
// 全局注册一次
$ui.on('hello', (e) => { /* e.id = 节点 id，值控件带 e.value */ });
```

**③ 进新页面用 push，刷新当前页用 render。**

```js
$ui.push(nextPageTree);    // UI 栈 +1，返回键能逐层退
$ui.render(thisPageTree);  // 替换当前层，不加层级
```

这三条搞混是新手 90%  bug 的来源，详见 [第 3 章](03-UI树基础.md) 和 [第 10 章](10-页面栈与返回.md)。
