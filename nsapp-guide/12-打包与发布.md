# 第 12 章 · 打包与发布

---

## 12.1 打包命令

```bash
cd <仓库根目录>/server
node pack.js
```

做的事：

1. 扫 `apps/` 下所有含 `package.json` 的目录
2. 校验 `id`（缺省用 `uuid`）与 `main` 文件存在
3. `zip` 成一个 `.nsapp`（内容在 zip 根）
4. 复制一份 `.zip` 别名
5. 算 md5，写进 `data/built.json`

```
server/data/apps/<id>.nsapp     # 安装包
server/data/apps/<id>.zip       # 同内容别名
server/data/built.json          # 清单
```

### 自动排除（防「包里有包」）

```
*.nsapp  *.zip  *.nsapps  *.DS_Store  _*.js  dist/*
```

> 这条排除是必须的：不排除的话构建产物会被递归打进包，体积翻倍 + 装出来带垃圾，
> 每打一次多一层。

### 手动打包单个应用

```bash
cd apps/my-app
zip -r -q ../my-app.nsapp . -x '*.nsapp' -x '*.zip'
```

## 12.2 图标规范（硬性）

**每个应用必须有 `assets/icon.png`，且必须正方形（推荐 256×256）。**

| 要求 | 说明 |
|---|---|
| 格式 | PNG（也支持 jpg/webp） |
| 尺寸 | 256×256 |
| 比例 | **必须正方形** |
| 唯一性 | **每个应用必须不同** |

理由：

- 启动器/商店把图标渲染进 64dp 方形槽位，`ContentScale.Fit` 只保证不变形，
  非正方形会留大片空白，视觉上偏小
- ⚠️ 切勿把 **TV banner（320×180 横条）** 当图标
- 曾有多个应用共用同一张图，用户在启动器里无法分辨
  —— 用户在启动器里无法分辨

**打包会拦**：`server/pack_nsapps.sh` 发现任何应用缺 `assets/icon.png` **直接中止打包**。

### 批量生成

```bash
# 全部应用
python3 server/make_app_icons.py

# 指定应用
python3 server/make_app_icons.py my-app

# 预览拼图 → dist/app-icons-preview.png
python3 server/make_icon_sheet.py
```

（纯 stdlib，无 PIL 依赖，输出 256×256）

## 12.3 商店服务端

```bash
cd <仓库根目录>/server
node server.js          # 默认 0.0.0.0:8788 (可用 PORT/HOST 覆盖)
PORT=9000 HOST=127.0.0.1 node server.js    # 换端口/监听地址
```

### 端点

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 商店首页（HTML） |
| GET | `/index.json` | **应用清单**（built.json + pushed.json 合并，每次实时合并） |
| GET | `/apps/<id>.zip` | 应用包 |
| GET | `/apps/<id>/<file>` | 应用源文件（图标等） |
| POST | `/api/rebuild` | 重新打包 `apps/` 目录 |
| POST | `/api/push` | 推送外部应用（无需本地源码目录） |

> **`node pack.js` 之后不用重启服务端** —— `/index.json` 每次请求都重新合并。
> 手机商店页点「刷新」即可看到新应用。

### 手机连接

1. 查电脑局域网 IP：`ip addr` / `ifconfig`
2. 手机连**同一 Wi-Fi**
3. 基座 → 设置 → 应用商店 → 填 `http://<服务器地址>`
4. 商店页刷新 → 点安装

> 连不上先查防火墙：`sudo ufw allow <端口>`

## 12.4 .nsapp 与 .nsapps

### .nsapp（单应用）

`.nsapp` 就是 zip 包本身，与 APK 同级概念。**下载到手机点一下即可安装**
（基座注册了文件关联）。

zip 根目录即应用根目录：

```
package.json      # 必填
main.js           # 必填
assets/           # 图标
node_modules/     # 可选
```

### .nsapps（多应用一键装包）

一个 zip 内含多个 nsapp 顶层目录：

```
nodeshell-apps-all.nsapps
├── <应用id>/
│   ├── package.json
│   └── main.js
├── <另一个应用id>/
│   ├── package.json
│   └── main.js
└── ...
```

判定：zip 根级**无** `package.json` 且存在 **>1** 个顶层子目录各含 `package.json`。

点开 → 基座列出包内所有应用（含已装版本标注）→ 用户点「全部安装」→
逐个子目录 `repackZip()` 重打包成标准 `.nsapp` → 走同一安装流程。

### 打包全部应用为 .nsapps

```bash
bash server/pack_nsapps.sh
收集 `apps/` 下所有应用，加上仓库外应用（源目录可用 `NS_EXT_APPS` 覆盖），
清理测试脚本与 node_modules，**硬校验必需应用存在 + 所有应用有图标**，任一不满足直接退出。

## 12.5 推送应用到商店

```bash
# 商店地址（填你自己的）
STORE="<你的商店地址>/api/v1/nodeshell"
PUSH_TOKEN="<你的推送令牌>"

# 推送
curl -X PUT "$STORE/api/push/my-app" \
  -H "x-push-token: $PUSH_TOKEN" \
  -H "x-push-name: 我的应用" \
  -H "x-push-version: 1.0.0" \
  -H "Content-Type: application/octet-stream" \
  --data-binary @apps/my-app/my-app.nsapp
```

成功返回 `{"code":0,"msg":"ok",...}`；偶发 **522 重试即可**。

### 校验惯例

推完从 `…/pushed/<id>.nsapp` 拉回，比 md5 与本地一致才算成功：

```bash
curl -s "$STORE/pushed/my-app.nsapp" -o /tmp/check.nsapp
md5sum /tmp/check.nsapp apps/my-app/my-app.nsapp
```

参考脚本：仓库 `server/push_all_to_store.sh`

> ⚠️ 商店推送接口**不吃 description**（列表里描述为空 = 正常现象）。

## 12.6 安装入口（三种）

| 入口 | 示例 | 说明 |
|---|---|---|
| 商店 | 基座 → 应用商店 → 安装 | 从 `index.json` 下载安装 |
| 链接 | `nodeshell://install?url=<包地址>` | 手机浏览器/聊天点链接直装 |
| 文件 | `xxx.nsapp` / `xxx.nsapps` | 点文件或文件管理器选择安装 |

链接还支持从商店安装：`nodeshell://install?server=<商店地址>&id=<应用id>`

## 12.7 升级

1. 改代码，**`version` 必须递增**
2. `node pack.js`
3. 商店页刷新 → 显示「升级」→ 点

> ⚠️ version 不递增，商店不给升级按钮（基座按 versionName 判断）。
> ⚠️ 改了 `id` = 全新应用，与旧应用共存。
