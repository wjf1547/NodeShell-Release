## 13.1 调试器 Console

基座应用页顶栏右侧 **🛠 调试器** 按钮 → 底部弹出面板，两个页签：

| 页签 | 内容 |
|---|---|
| **Console** | 你的 `console.log`、UI 契约校验告警、应用 error |
| **Insight** | 运行状态/内存等 |

```js
console.log('载入完成, items =', state.items.length);
console.error('失败了', e.message);
```

**养成习惯**：每个事件 handler 的第一行、每次网络请求的返回，都 log 一行。
比盲猜快 10 倍。

## 13.2 UI 契约校验（0.1.64+）

基座在 `$ui.render`/`$ui.push` 时用 `ui-schema.json` 校验你的树，
**只报不拦**（warn 进 Console，不抛错）。

### 报什么

| 级别 | 场景 | 示例 |
|---|---|---|
| **ERR** | `type='list'` 写了 `node.children` | `❌ type='list' 不读 node.children → 子节点整块丢弃。list 的外围节点请写 props.header/footer/actions/secondaryActions` |
| **ERR** | `props.children` | `❌ type='card' 的 props.children 会被静默丢弃 → 子节点整块空白。children 必须写在【节点层】(与 props 平级), 不是 props 里` |
| **ERR** | 未知控件 type | `❌ 未知控件 type='textt' → 会渲染红色兜底卡片` |
| **ERR** | 节点缺 type | `❌ 节点缺 type` |
| **WARN** | 写了控件不读的 props 字段 | `⚠️ type='text' 不读 props.textAlign → 静默失效 (合法: align,bold,color,...)` |
| **WARN** | 数据行不读某字段 | `⚠️ type='list' 数据行不读 'onClickX' (合法: avatar,badge,icon,...)` |
| **WARN** | 按钮缺 onClick | `⚠️ 按钮 '确定' 缺 onClick → 点了没反应` |

### 为什么是「只报不拦」

若直接抛错，现有应用里所有已存在的静默失效写法会让它们当场起不来。
先让问题可见，逐批修完再考虑升级为拦截。

### 关掉

```js
$ui.setSchemaCheck(false);
```

（一般不用关。真有大量历史 warn 又不想看，再关。）

## 13.6 本地测试（无头）

应用侧想单测逻辑，可以把 `$http`/`$storage` 等 mock 成 `{}`，直接 `node` 跑：

```bash
node apps/<你的应用>/main.js    # 能跑通说明没有语法/顶层引用错误
```

更完整的做法是参考仓库内某些应用自带 `_test_*.js` 的形式：把桥接对象
mock 掉，用 `assert` 逐条校验纯函数。

## 13.8 让 AI 直接改这个应用（MCP，0.2.37+）

上面 13.1~13.7 是「人自己调」。0.2.37 起还有一条路：**把手机上的应用源码直接交给
外部 AI 客户端**（Claude Desktop / Cursor / Claude Code），让它自己「写 → 跑 → 读日志 → 改」。

手机端：**设置 → MCP 调试端点 → 打开「已开启」→ 保存并生效**（默认关，因为等于把
「往手机里写代码并执行」的权限交给能连上它的程序）。打开后设置页直接显示 MCP 地址与
Token，各带一个复制按钮。电脑端配置见 [`docs/MCP.md`](../../MCP.md)。

对写应用最有用的是那两个「以前只能靠人点」的工具：

| 工具 | 什么时候用 |
|---|---|
| `ns_get_docs` | **先调这个**。它返回控件表 + 四条铁律，不调就会编控件名 —— 而编错只渲染成灰卡片、**日志不报错** |
| `ns_send_event` | 改完点一下那个按钮，看界面是否真变（`uiChanged`）+ 日志里是否出现你的事件名 |
| `ns_get_state` | 除了树，还要看 **`schemaIssues`** —— 控件名写错时 `launchError` 是 null、日志不报错，只有这里会说「type='cardx' 不认识」（0.2.38+） |
| `ns_patch_file` | 改一个字符串**别整份重传**。只传 `old`/`new`，默认要求原文唯一命中；命中多处会拒绝并给行号（0.2.46+） |
| `ns_scan` | 交付前自查密钥。结果已脱敏；默认只扫应用源码，不扫 `node_modules`/`.trash`（0.2.46+） |
| `ns_purge_trash` | `ns_delete_file` 删掉的东西进 `.trash` 只会增，用这个倒掉。默认预演，`confirm:true` 才真删（0.2.46+） |

> **0.2.38 起「失败」长什么样**：`ns_write_file` 写完会先做语法检查，不过就
> `ok:false, written:false` + `syntaxError.line/source`，**文件不落盘**（不会给你留一份
> 坏代码）；启动崩了会给 `launchErrorDetail` 的行号；树有结构错误则 `ok:false` +
> `schemaIssues`。看到 `ok:false` 就去读那条错误，**不要重试同样的内容**。
> 另外 `ns_launch_app` 成功后**手机屏幕会同步切到那个应用** —— 你在电脑上看到的
> 和用户看到的是同一个界面。

> ⚠️ 不要拿它替代 13.7 的真机清单。它能验证「逻辑对不对」，验证不了「手感 / 字体 /
> 弱网」这些 —— 那些还得自己上手。

## 13.9 让手机上的 AI 直接造应用（0.2.67+）

13.8 那条路要求**有电脑**：装 MCP 客户端、配地址和 Token。可这是「手机优先」的基座，
很多人手上就一台手机 —— 于是 0.2.67 把同一条能力搬到了手机上：

**设置 → 💬 AI 助手对话框 → 说一句话 → 它自己写 → 自己启动 → 自己看日志 → 自己改。**

不需要连电脑，不需要开 MCP 端口。跑的是和 `ns_agent` **同一个函数**
（`runner.runAgentTask`），26 个工具一模一样。

### 第一次用要配什么

**设置 → 🤖 AI 助手**，四件事：

| 项 | 说明 |
|---|---|
| 服务商 | OpenAI 兼容（DeepSeek / 通义 / Kimi / Groq / 本地 vLLM 都算）或 Anthropic |
| API Key | 只存在手机本地，日志里永远是 `已配置(N chars)` |
| Base URL | 留空用默认；第三方中转**必须**带 `/v1`（如 `https://xxx.com/v1`） |
| 模型名 | **点开就是下拉**（0.2.69+）。进页面会自动拉一次清单，也可点「↻ 刷新清单」手动重试；拿不到就显示内置清单（列表里会标「内置清单」）。清单里没有的服务商点最后一项「✎ 手动输入…」。**必须真选中一个**（0.2.70 起没有「用默认」了 —— 留空时程序会拿 gpt-4o-mini 去打你的服务商，第三方基本都回 400/404） |

> **为什么模型改成下拉了**：以前要你自己去服务商文档里抄一个模型名。抄错一个字
> 不会立刻报错 —— 要跑**一整轮**（system prompt + 26 个工具定义 ≈ 几千 token）
> 才看到一句 404。而 `GET /models` 是一行就能问出来的事。
>
> 拉回来的清单是**你这个 key 真能用**的；内置清单只在拉取失败/还没填 key 时兜底，
> 所以下拉框永远不会空。看到「已显示内置清单」说明这次是兜底的，但你仍然可以选 ——
> 只有拿不准时再去「测试连接」验一下。
>
> **默认排序是「便宜好用」在前**（`gpt-4o-mini` / `claude-sonnet-4-5`）。一次造应用
> 的任务动辄几十万 token，拿最强的模型当默认，一晚上能把一个月额度烧完。

**0.2.76 起不再有任务级预算上限**（步数 / token / 时限三道闸都已去掉）。
循环会一直跑到「模型不再调工具」自然结束，或你点「取消」主动停下 —— 与通用
agent 一致。这么做是为了不再出现「东西没做完、却说是预算用完」这种假失败。

要控制成本，靠的是**把任务说清楚**（见 13.10 的四段式提示词），而不是一个会
把半截任务掐掉的数字。真跑飞了就点「取消」：当前这一轮工具会跑完（避免写出
半个文件），下一轮开头就收尾。

> 单次请求仍受服务商自己的 `maxOutputTokens` 限制，超长工具结果回填也会被截断
> （截断文案会明确告诉你「已截断 + 原始长度 + 怎么拿更多」）—— 这些是协议层
> 的保护，不是「跑到一半把任务判失败」的闸。

配完先点 **「测试连接」**。它只发一个 16 token 的最小请求，能立刻分辨
`没配 key` / `key 错了` / `余额不足` / `网络不通` —— 而直接跑 agent 要白烧一整轮
（system prompt + 26 个工具定义 ≈ 几千 token）才看到一句 401。

### 对话框长什么样

```
┌─────────────────────────────────┐
│ ←  AI 助手                       │
├─────────────────────────────────┤
│ ┌ 你说 ─────────────────────┐   │
│ │ 做一个番茄钟，25 分钟倒计时  │   │
│ └───────────────────────────┘   │
│ ┌ AI ───────────────────────┐   │
│ │ 好的，我先看一下文档。      │   │
│ │ [第 3 步 · 已用 12 秒]      │   │
│ │  get_docs → write_file →    │   │
│ │  launch_app → read_log      │   │
│ │  ───────────────────────    │   │
│ │ 做好了。启动后能看到 25:00… │   │
│ │  ↻ 接着改                   │   │
│ └───────────────────────────┘   │
├─────────────────────────────────┤
│ [说点什么…              ] [发送]│
└─────────────────────────────────┘
```

**工具轨迹那一行是唯一能自证「它还活着」的东西。** 一个任务可能调 20 次工具、跑三分钟，
中途模型只会回「好的，我来看看」这种话。三种状态要分清：

| 状态 | 意思 |
|---|---|
| 正在思考 | 请求已发出，等模型回话（慢是这个阶段） |
| 正在调用 `ns_write_file` | 模型点名要干这件事，正在执行（**这里才是真在改东西**） |
| 正在收尾 | 模型说完了，正在整理结论 |

**离开不丢**：对话框是独立一页，你按返回去看应用做出来什么样，AI 照样在跑；回来还在。
跑着的时候发送按钮变成**取消**。

> 取消后**当前那个工具调用会跑完**才停 —— 半途打断可能留下写了一半的文件，
> 那比多等两秒难查得多。

### 提示词怎么写才不瞎改

模型拿到的是 26 个工具和一个大空白，**你说得越具体它越省步数**：

| ❌ 这样写 | ✅ 这样写 |
|---|---|
| 做个应用 | 做一个番茄钟：25 分钟倒计时、开始/暂停/重置三个按钮、结束时 `$alarm` 响一声 |
| 帮我修一下 | 计算器按 `=` 没反应，Console 里没报错，检查 `onClick` 有没有接上 |
| 好看一点 | 主色用 `#4A90D9`，卡片圆角 12，列表项高 56 |

几条实测有效的经验：

- **一次一件事**。让它「顺便把配色也改了」会让它分不清哪一步把界面改坏了。
- **报症状不报结论**。「按钮点了没反应」是症状，「onClick 没接」是结论 —— 你的结论
  可能是错的，而 AI 会顺着你的错结论一路改错。
- **长任务换一句话接着改**，别在同一个提示里塞十个需求。跑完会出「↻ 接着改」，
  点它继续；它记着上一轮做了什么。

### 它失败的时候

失败几乎都是这四类，界面上会直接说：

| 提示 | 真实含义 | 怎么办 |
|---|---|---|
| 没配置 API Key | 设置里的 key 是空的 | 去设置页填，或点「测试连接」看具体哪步错 |
| 任务被取消 | 你点了「取消」 | 已经做完的部分在手机上，接着说一句就会带上前面的上下文 |
| 鉴权失败 / 余额不足 | key 错，或钱不够 | 充值或换 key。**重试同一个请求永远不会好** |
| 限流 | 请求太密 | 等一会儿再点 |

> AI 造应用不是一次就能成。**看工具轨迹**判断它卡在哪：重复调 `ns_read_file` 读同一个
> 文件 = 它在找不存在的东西；`ns_write_file` 反复 `ok:false` = 代码有语法错，它还没找对；
> 一直在 `ns_get_docs` 打转 = 它在猜控件名。
>
> 这时候**你接手更快**：去看 Console，或者直接在对话框里告诉它「别猜了，控件叫 `segmented`」。

### 和 13.8（电脑端 MCP）的关系

两条路共用同一套工具循环、同样的错误分类，且都**没有任务级预算闸**（0.2.76 起）。差别只在**谁在调用**：

| | 手机上（13.9） | 电脑上（13.8） |
|---|---|---|
| 入口 | 设置 → 💬 AI 助手对话框 | MCP 客户端调 `ns_agent` |
| 要开 MCP 端口 | **不用**（工具表懒建，不监听） | 要 |
| 谁付 token | 手机上配的那个 key | 电脑客户端自己的 key |
| 适合 | 随时随地改一下 | 大改、配合 IDE、多轮长对话 |

> ⚠️ 两条路都**走直连，不经出口代理**（用户 2026-10-22 定的规矩）。
> 你的机场挂了不影响 AI 能不能用，反过来也一样。

### 两件刻意「不做」的事

看对话框的时候别以为是漏做了：

| 不做 | 为什么 |
|---|---|
| **不渲染 markdown** | 要一个几百 KB 的解析库，而这一屏只需要回答「干完没、干成什么样」。回答里的 `**粗体**` 会原样显示成星号 |
| **不做流式打字（逐字冒出来）** | 流式响应的 `tool_calls` 是**分片 JSON**，拼接是最容易出静默 bug 的地方 —— 拼错一个字符，整个工具调用参数就废了，而界面上看着只是「AI 回得有点怪」。宁可等整段回来一次显示 |

> **对话历史现在会落盘（0.2.76 起）**，与这里的「两件不做」不是一个层面的取舍：
> 那两条是为了「少一个解析库 / 少一类静默 bug」，而历史不落盘直接造成的是
> **功能缺失** —— 用户原话「对话异常后又得重新开，重新对话不记得之前的记录」，
> 而模型每轮从空上下文开始，「刚才让你改的那个文件」它根本不知道是哪个。
>
> 现在的规则与通用 agent 一致：**不清空就一直记得**。
>
> - 存在应用私有目录（`<data>/ai-chat.json`），不在 `/sdcard` 上，卸载即删；
> - 只存对话 messages（你的话 + 模型的话 + 工具调用记录），**不存 apiKey**；
> - 上限 `AI_CHAT_MAX_MESSAGES = 120` 条，超了从最旧的丢（**从 user 边界裁**，
>   不会把「assistant.tool_calls + 紧随的工具结果」拆成半截，那样下一轮请求会 400）；
> - 除了点「清空」，没有别的东西会删它 —— 包括任务异常、runner 崩溃、应用重启。
>
> 设置 → AI 助手 → **「会话」** 卡片能直接看到「记住了 N 轮 / 共 M 条」并一键清空。
> 这一版之前的老版本存过的超长会话，载入时会自动裁一次。

## 13.10 AI 造应用实操：从一句话到能用的应用

13.9 讲的是「这个功能在哪、怎么配」。这一节讲**怎么真的做成一个应用**。

### 第一句话该说什么

一个能一次跑通的提示，通常包含四块：

```
[做成什么] + [核心交互] + [数据存在哪] + [怎么算做完]
```

实例：

> 做一个记账应用。首页列出本月所有支出（金额、分类、日期），顶部显示本月合计。
> 点右下角加号弹表单填金额/分类/备注。数据用 `$kv` 存本地，重启还在。
> 做完启动给我看，能加两笔、合计对得上就算完成。

四块对照：

| 块 | 缺了会怎样 |
|---|---|
| 做成什么 | 它会做一个「差不多」的东西，你不想用的那种 |
| 核心交互 | 出来一个静态页面，点哪儿都没反应 |
| 数据存在哪 | 它可能用 `$storage` 也可能不用 —— 重启数据没了 |
| 怎么算做完 | 它写完文件就报「做好了」，实际首屏白屏 |

### 它干活的时候你在干什么

**别关对话框，但也别干等。** 三分钟里你可以：

1. **盯着工具轨迹认节奏**。正常顺序长得像
   `ns_get_docs → ns_write_file(index.js) → ns_write_file(icon) → ns_launch_app → ns_get_state → ns_read_log`。
   如果 `ns_launch_app` 之后一直 `ns_read_log` 不出来，说明它开着一个等 180 秒的请求。
2. **去 Launcher 看那个应用真长什么样**。`ns_launch_app` 成功时手机屏幕会自动切过去 ——
   你看到的和 AI 看到的是同一个界面。
3. **准备好下一句话**。它跑完会告诉你哪儿没做完，你接着说就行。

### 交付前自己过一遍

AI 说「做好了」只代表**它认为**做好了。四件事必须自己确认：

- [ ] **首屏不是白屏**（最常见：树写对了但数据是空的，一直 loading）
- [ ] **每个按钮真的点过**（AI 最容易漏 `onClick` —— 基座对「事件没人接」只静默 warn）
- [ ] **杀应用重进，数据还在**（它是不是真用了 `$kv`/`$prefs`）
- [ ] **Console 里没有 ERR**（尤其 `type='cardx' 不认识` 这类控件名拼错）

对这四条逐条跑一遍，比让它自己说十遍「已完成」有用。

### 一个真实的迭代节奏

```
你：做一个倒计时应用，能设分钟数，倒计时结束响一声
AI：（28 步，3 分钟）做好了，启动后能看到 25:00
你：（打开看）数字不走了 ← 报症状
AI：（6 步，40 秒）找到问题，$alarm 的回调没接上，已修
你：（再看）走了，但响铃没反应 ← 还是报症状
AI：（4 步，30 秒）闹钟设为 0 秒后被立即取消，改成先设再启动
你：好了
```

**这是正常的，不是失败。** 一次就成的任务通常是「小到不值得用 AI」的任务。
真正省时间的是第 2~4 轮 —— 那些「我说不清但看到就知道不对」的小错，
它改起来比你翻文档快得多。

### 什么时候别用它

| 情况 | 为什么 |
|---|---|
| 你完全不知道要什么 | 它会替你猜，猜出来的东西要改的比你写的还多 |
| 只是改一个字符串 / 换个颜色 | 直接进 IDE 改，2 秒的事，AI 要烧 5k token |
| 需要联网 API 的应用 | 它能写，但拿不到真实响应 —— 你要先自己把 API 调通、把返回样例给它 |
| 交付给别人的应用 | AI 写的代码没人审过。自己用可以，给别人前过一遍 `ns_scan` 和 Console |

## 13.11 26 个工具的完整清单

13.8 那张表是「对写应用最有用的几个」。这里是**全量 26 个** —— 手机上对话框里的 AI
用的就是这一套，电脑端 `ns_agent` 用的也是这一套（同一个 `makeTools`）。

### 读

| 工具 | 干什么 |
|---|---|
| `ns_get_docs` | 返回控件表 + 四条铁律。**AI 的第一件事，不调就会编控件名** |
| `ns_find_example` | 按关键词找现成示例代码（`pager` / `list` / `video` …） |
| `ns_list_apps` | 列出所有应用（id / 名称 / 有没有源码） |
| `ns_list_files` | 列某个应用目录下的文件 |
| `ns_read_file` | 读源码（大文件会截断，**明确告知**截断位置和怎么读更多） |
| `ns_get_state` | 当前 UI 树 + **`schemaIssues`**（控件名写错的唯一线索）+ `launchError` |
| `ns_get_layout` | 只取布局骨架（节点路径 + 尺寸/位置），排查「为什么这个按钮在屏幕外」 |
| `ns_read_log` | 应用 Console 日志（`console.log` / error / 基座 warn 都在） |
| `ns_screenshot` | 截一张当前界面图（视觉回归 / 确认真的画出来了） |

### 写

| 工具 | 干什么 |
|---|---|
| `ns_create_app` | 建一个新应用（写 `package.json` + 目录骨架） |
| `ns_write_file` | 写/覆盖源码。**写完先做语法检查，不过就不落盘**（不会留坏代码） |
| `ns_patch_file` | 改一段字符串。只传 `old`/`new`，要求唯一命中；命中多处会拒绝并给行号 |
| `ns_delete_file` | 删文件（进 `.trash`，可恢复） |
| `ns_rename_app` | 改应用名/图标 |
| `ns_delete_app` | 删整个应用 |
| `ns_scan` | 扫源码里的密钥/Token（结果已脱敏） |
| `ns_rollback` | 回滚到上一个检查点 |

### 跑与点

| 工具 | 干什么 |
|---|---|
| `ns_launch_app` | 启动应用。**成功后手机屏幕同步切过去** —— 两边看到的是同一个界面 |
| `ns_eval` | 在应用沙箱里跑一段 JS（读运行时变量、临时验证一个假设） |
| `ns_send_event` | 替用户点一下/滚一下。返回 `uiChanged` —— **这是「真变了没」的唯一证据** |
| `ns_get_storage` | 读 `$kv` / `$storage` / `$prefs` 里的数据 |
| `ns_set_storage` | 直接改存储（造测试数据 / 清状态） |
| `ns_clear_storage` | 清空一个应用的存储 |
| `ns_purge_trash` | 倒掉 `.trash`（默认预演，`confirm:true` 才真删） |

### AI 自身

| 工具 | 干什么 |
|---|---|
| `ns_agent` | 一句话派一个 agent 任务（**电脑端用；agent 自己的工具表里会排除它**，防递归） |
| `ns_agent_doctor` | 不花 token 的配置自检（`ping:true` 才发 16 token 的最小请求） |

> **为什么 agent 的工具表要排除 `ns_agent` 自己**：模型能调自己就意味着一次任务里
> 再开一个任务，任务会无限套娃、再也不会自然停下（0.2.76 起没有预算闸兜底，
> 这一条更关键了）。所以递归通道直接被拿掉 —— 想停只能靠模型自己停或用户取消。

## 13.12 AI 相关的高频翻车点

从 0.2.65 ~ 0.2.67 三版里攒的，都是「看着能跑、实际不工作」的：

| 症状 | 根因 | 怎么认出来 |
|---|---|---|
| AI 说「工具不存在」，然后自己绕圈 | 工具表缺依赖（`ctx` 里少一个函数） | 工具轨迹里同一个工具反复失败 + 模型开始回「我换个方法」 |
| 一直显示「正在思考」，十分钟不动 | 上游模型服务挂了，或卡在一个长请求上 | 看「已用时」在涨但步数不动 = 卡在一个请求上；点「取消」收尾 |
| 「做好了」但打开是白屏 | 树写对了、数据是空的 | `ns_get_state` 的 `schemaIssues`；或直接看 Console |
| 反复改同一个文件改不好 | 语法错没找对位置 | `ns_write_file` 连着 `ok:false`，`syntaxError.line` 指向同一行 |
| 一直绕圈不结束 | 提示词太模糊，它在猜 | 看轨迹：大量 `ns_read_file` = 在找不存在的东西；点「取消」或把任务说具体 |
| 上次能做的事这次不行 | 换了个模型（同服务商不同型号能力差很多） | 设置页的模型名 |
| 手机上配好了，电脑端 MCP 说没配 | 两条路各有各的 key | 手机 key 在设置页，MCP 的 key 在客户端配置里 —— **不是同一个** |

> **一条通用判据**：AI 造的每一个应用，**最终都要你自己在真机上看一眼**。
> 它能验证「逻辑对不对」（日志、树、事件），验证不了「手感、字体、弱网」——
> 后者只有人的眼睛能判。
