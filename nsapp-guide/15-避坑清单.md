# 第 15 章 · 避坑清单

每一条都来自**线上真实 bug**。违反任一规则可能导致返回层级错乱、设置丢失、
播放异常等看起来「基座有 bug」的问题 —— **排查前先对照本清单**。

---

## 15.1 页面栈与返回（最高优先级）

### 规则 1：进入新页面必须用 `$ui.push`，刷新当前页内容才用 `$ui.render`

```js
// ✅
$ui.push({ type:'root', props:{ title: dir.name }, children:[{type:'loading'}] });
$ui.render({ type:'root', props:{ title:'列表' }, children:[/* 刷新 */] });

// ❌ 进多层目录也用 render —— UI 栈永远只有 1 层，
//    返回键一按就直接退到首页/退出应用（某个云盘应用 0.1.11 之前的实际 bug）
```

### 规则 2：应用可以有自管业务栈，但绝不能自己管 UI 栈

- 应用侧可用 JS 数组（如 `pathStack`）记录业务路径
- **UI 栈完全由基座统一管理**

### 规则 3：返回键由基座统一处理

```js
// ✅ 应用内模态状态直接消费返回键
$ui.setBackHandler(() => {
  if (selectMode) { selectMode = false; renderPage(); return true; }
  return false;
});

// ✅ $app.on('back') 只同步业务状态
$app.on('back', () => { if (pathStack.length > 1) pathStack.pop(); });

// ❌ 在 back 里调 $ui.pop / $ui.render —— UI 栈基座已 pop，再 pop 会把上一层也弹掉
// ❌ 用 $ui.push 占位层让返回键触发 appBack（已废弃的 hack）
```

### 规则 4：`$ui.render` 不要重建整棵页面结构去「恢复」上一页

返回后的页面内容由基座保留原 UI 栈帧，应用只需在 `back` 里同步数据，
需要刷新时再 `render` 当前栈顶。

### 规则 4b：滚动位置由基座自动记忆

**应用不要自己存/恢复滚动位置**（0.1.63r20+）。
想让结构相似的不同页面各自记忆位置 → 给 root 加稳定 `id`。

### 规则 4c：`onEndReached` 必须自己判「还有没有下一页」

```js
// ✅
$ui.on('more', () => loadPage(false));
async function loadPage(fresh) {
  if (!fresh && c.loaded && !c.hasMore) return;   // 什么都不做
  c.hasMore = list.length === PAGE_SIZE;
  c.loaded  = true;
}
```

用 **`loaded` + `hasMore`** 两个标记判，不要用 `items.length > 0` 这类间接信号。

## 15.2 配置持久化

### 规则 5：用户配置必须通过 `$prefs.set` 落盘，键带 `prefs.` 前缀

```js
// ✅ 重启保留
$prefs.set('prefs.proxy', true);
// ❌ 只写内存变量 → 重启即丢（某个云盘应用 v1.2.0 旧 bug）
SETTINGS.proxy = true;
```

### 规则 6：配置读取要给默认值兜底

```js
function pref(key, def) {
  const v = $prefs.get(key);
  return (v === undefined || v === null || v === '') ? def : v;
}
```

### 规则 6b：从数组里「删除某一项」必须按索引删除

```js
// ❌ 永远删不掉（0.1.63r18 修复的 9 个应用真实 bug）
saveServers(loadServers().filter((x) => x !== s));
// 原因: loadServers() 内部 JSON.parse 每次返回全新对象 → 引用恒不相等

// ✅ 按索引删 + 名称兜底
function delServer(i, s) {
  const l = loadServers();
  if (l[i] !== undefined && (l[i].name||'') === (s.name||'')) l.splice(i, 1);
  else { const k = l.findIndex(x => (x.name||'') === (s.name||'')); if (k >= 0) l.splice(k, 1); }
  saveServers(l);
}
```

**凡见 `.filter((x) => x !== someObj)` 一律是 bug。**

## 15.3 网络与出口代理

### 规则 7：API 用 `$http`，播放用 `@shell/stream`，**默认不碰 `$mhttp`**

```js
// ✅ 默认写法：请求直连、播放直连源站
const r = await $http.get(apiUrl, { timeout: 15000 });
const url = await require('@shell/stream').url(raw, { transform: decrypt, contentType:'video/mp4' });
```

- `$http` **永远直连真实目标**（不受代理开关影响）→ API/页面一律用它
- 播放走 `@shell/stream` 的 `url()` / `m3u8()` / `custom()`，也是直连源站
- `$mhttp` 是**出口代理版**：只有在用户明确要求走代理时，才在那一次调用里使用它
- ❌ 应用自连节点 / 自带代理开关 / 硬编码节点 IP 或伪装 Host

## 15.4 播放与资源

### 规则 8：`$media.open` 是内嵌迷你播放器，应用不要另起界面

全屏/旋转/倍速/手势全部由基座提供，应用不要自绘控制条。

### 规则 9：传 `infoUrl` 给 ℹ 信息弹窗展示原始链接

`infoUrl` 必须是**端点转换前/解密前的源直链**，不是 `$mhttp.url()` 返回的本地 `/s/<token>` 地址。

### 规则 12：播放/页面兜底不得依赖「服务端某个页面」

商店服务器只托管 `index.json` / 应用包 / 图标，**没有** `player.html` 之类的通用页面；
且 `$shell.server` 可能为空。

```js
// ❌ 白屏（一个直播应用的报障根因）
$webview.open({ url: $shell.server + '/player.html?src=' + u });

// ✅ 原生播（Media3 支持 HLS/mp4/FLV），播不了由基座浮层报错
$media.open({ url: u, infoUrl: u, type:'video', title, autoPlay: true });
```

应用需要的页面/资源应**自带在应用包内**（`assets/`），或由 `@shell/stream` 的 `custom()` 自托管。

## 15.5 事件与数据

### 规则 10：事件回调用 `e.id` 回查数据，不要用闭包捕获索引/对象

```js
// ✅ 从当前栈顶数据里按 id 回查（数据永远是最新的）
$ui.on('play', (e) => {
  const f = top().items[parseInt(String(e.id).slice(1), 10)];
  if (f) play(f);
});
```

`$ui.on` 的事件处理器注册一次，页面栈变化后旧闭包里的对象可能已过期。

### 规则 11：配置/数据变更后必须重渲染让 UI 即时反馈

保存设置、切换状态后调 `renderPage()` / `$ui.render` 刷新当前层，
否则 UI 显示与真实状态不一致（**开关回弹、label 不更新的根因**）。

---

## 15.6 图标

### 规则 11：每个应用必须有 `assets/icon.png`，且必须正方形（推荐 256×256）

- **必须正方形**（方形槽位 + `ContentScale.Fit`）
- **每个应用必须不同**（曾三个应用共用一张图，用户无法分辨）
- ⚠️ 切勿把 TV banner（320×180 横条）当图标
- 打包自检会拦：`server/pack_nsapps.sh` 发现缺图标直接中止

## 15.7 写法层的高频错误

### props 与 children 分层

```js
// ❌ props.children → 整块静默丢弃（有应用栽过）
{ type:'card', props:{ children:[...] } }

// ✅ children 与 props 平级
{ type:'card', props:{ /* 字段 */ }, children:[...] }
```

### list 不读 children

```js
// ❌ actions 写进 children → 静默丢弃（有应用的真实 bug）
{ type:'list', props:{ items }, children:[{ type:'actions', ... }] }

// ✅ 走 props.actions / props.header / props.footer / props.secondaryActions
{ type:'list', props:{ items, actions:[...], footer:[...] } }
```

### root scroll=false 时，list 必须独占 + footer 放底栏

```js
// ❌ list 与 actions/fab/输入栏 平级 → list 拿不到 weight(1f)，
//    底栏被挤出可视区或点击命中不到（一个多页面应用的真机 bug）

// ✅ root scroll=false 的页面, list 必须独占并带 weight;
//    actions/fab/输入栏一律放进 list 的 footer
{ type:'list', props:{ items, footer:[
  { type:'actions', props:{ align:'fill', items:[...] } },
  { type:'space', props:{ height:72 } },
]}}
```

### Lazy 组件不能进 scroll 容器

**0.2.21 起基座会自动分段处理，不再闪退** —— `root scroll:true` 里同时有普通节点与
`list`/`grid`/`tree` 时，基座把连续的普通节点分成一组包进自己的 `verticalScroll`，
Lazy 节点各自成段（它们本来就自己滚）。2026-10-28 实测 9 屏这种写法全部正常渲染。

⚠️ 但**仍然不要这么写**：

1. Lazy 本来就能滚，外面再套一层 = 两个滚动容器套一起，用户滑到那段会出现
   「双滚动条 / 滑不动」的手感问题（不崩，但很怪）；
2. 分段是根据**children 顺序**切的 —— 普通节点、Lazy、普通节点 会切成三段，
   你原本以为是一整页的滚动变成了「滚-停-滚-停」；
3. 嵌套在 `column` / `card` 里的 Lazy 不在分段范围内，真的还可能崩。

**正确写法**：要列表就让它独占整页（`root scroll:false` + `list` 带 `weight`），
底部栏放进 `list.props.footer`。要长表单才用 `root scroll:true`，里面别放 Lazy。

### fab / actions 是 children 里的节点

```js
// ❌ 当成 tree 顶层 key
{ type:'root', props:{...}, fab:{ text:'＋' } }

// ✅ children 数组里的节点
{ type:'root', props:{...}, children:[
  { type:'list', props:{...} },
  { type:'fab', props:{ text:'＋', onClick:'add' } },
]}
```

### fab 会盖住列表最后一项

`list` 的 `footer` 里加 `{ type:'space', props:{ height:72 } }`。

## 15.8 受控组件必须维护状态（0.1.90 新增控件的共性）

`tree` 的 `expanded`、`sheet` 的 `open`、`segmented` 的 `selected`、`search` 的
`filters[].selected`、`accordion` 的 `items[].expanded` —— 这些**全是受控**：基座只负责渲染你给的值 + 回传事件，
真正的状态在应用侧。

```js
// ❌ 常见错法 1: 收到事件不 render → UI 不变（箭头不转、面板不关）
$ui.on('treeExpand', (e) => { node.expanded = e.expanded; /* 忘了 render() */ });

// ❌ 常见错法 2: sheet 不处理 onChange → 关了又弹回来
$ui.on('doDelete', () => { doDelete(); /* open 还是 true */ });

// ✅ 正确: 改 state → render
$ui.on('treeExpand', (e) => { node.expanded = !!e.expanded; render(); });
$ui.on('doDelete',  () => { state.sheetOpen = false; doDelete(); render(); });
```

**规律**：凡是 props 里有个「当前状态」字段（`expanded` / `open` / `selected` / `value` /
`checked`）的控件，都遵循 `事件 → 改 state → render()` 这一条路。

## 15.9 健壮性

### 网络请求统一超时

```js
function withTimeout(p, ms) {
  return Promise.race([p, new Promise((_, rj) =>
    setTimeout(() => rj(new Error('请求超时')), ms))]);
}
```

别让 UI 卡死等待。

### 缺失 API / 低版本基座

```js
try {
  if ($shell.apiVersion < 1) throw new Error('基座版本过低');
  if (!$wifi || typeof $wifi.scan !== 'function') throw new Error('基座不支持 $wifi (需 0.1.6x+)');
  const r = await $wifi.scan();
  // ...
} catch (e) {
  $ui.alert({ title:'无法使用', text: e.message });
}
```

### 应用不要自己 pop

```js
// 吹牛 v1.0.1 的真机 bug: createGame() 成功后自己调了 $ui.pop()
// → 自己 pop 会把上层一起弹掉，表现就是「莫名其妙回主页」
// 修法: 改为 renderApp() 刷回大厅层重新渲染，不碰返回栈
```

### 流端点按 token 注册，应用退出自动注销

应用**无需手动清理**。多个播放器实例并发安全。

## 15.10 一分钟自检

写完应用，把这段在心里过一遍：

```
□ 进新页面用 push，刷新当前页用 render
□ 没在 back 里 pop / render「恢复」页面
□ onEndReached 判了 loaded + hasMore
□ 用户配置写 $prefs 且带 prefs. 前缀，读取有默认值兜底
□ 删数组项按索引，没有 .filter(x => x !== obj)
□ API 用 $http，播放用 @shell/stream（默认不用 $mhttp）
□ $media.open 没有 await
□ list 的 actions/header/footer 在 props 里
□ actions/fab/输入栏在 root scroll=false 时进了 list 的 footer
□ list/grid/tabs 没进 root scroll:true（不崩了，但会“双滚动”手感怪异）
□ 每个事件用 e.id 回查，不用闭包索引
□ 改完 state 一定 render()
□ 图标存在、正方形、不与他人重复
□ 没有依赖服务端不存在的页面
□ 受控控件 (tree.expanded / accordion.expanded / sheet.open / segmented.selected) 改完 state 后 render 了
□ sheet 处理了 onChange (把 open 改回 false)
□ tree 的 children 写在 items[] 里，不是 node.children
```
