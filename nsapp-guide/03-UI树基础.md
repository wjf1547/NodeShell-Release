# 第 3 章 · UI 树基础

这一章讲「界面到底是怎么描述的」。掌握了这一章，控件篇就是查表的事。

---

## 3.1 一个节点长什么样

```js
{
  type: 'text',        // 必填，控件类型
  id:   'title-1',     // 可选，事件回传用；不交互的节点不用给
  props: {             // 控件读的字段，全部放这里
    text: 'Hello',
    size: 18,
    bold: true,
  },
  children: [          // 可选，子节点数组（与 props 平级！）
    { type: 'text', props: { text: '子节点' } },
  ],
}
```

只有 4 个键：`type` / `id` / `props` / `children`。

---

## 3.2 ⚠️ props 和 children 是两层，别搞混

这是历史上「按钮没渲染」「卡片整张空白」的**唯一根因**。

**规则**：`props` 里只放控件读的字段；`children` 是**独立的键**，与 `props` 平级。

```js
// ✅ 正确：children 与 props 平级
{
  type: 'card',
  props: { text: '标题' },
  children: [ /* 子节点 */ ],      // ← 和 props 同级，不在它里面
}
```

```js
// ❌ 错误：children 写进了 props 里 → 整块静默丢弃（不报错，只是不显示）
{
  type: 'card',
  props: {
    text: '标题',
    children: [ /* 子节点 */ ],    // ← 错了，嵌在 props 内部
  },
}
```

一眼对照（只看 `children` 的位置）：

| 写法 | `children` 在哪 | 结果 |
|---|---|---|
| `{ type:'card', props:{...}, children:[...] }` | 节点层，与 `props` 平级 | ✅ 正常渲染 |
| `{ type:'card', props:{..., children:[...]} }` | `props` 内部 | ❌ 静默丢弃，整块空白 |

规则：

- **`props.*` 是控件读的字段**
- **`children` 是子节点数组，挂在节点上、与 `props` 平级**
- 只有 `root` / `card` / `column` / `row` / `drawer` 读 `children`
- **`list` 不读 `children`** —— 它的头/尾/操作栏必须写 `props.header` / `props.footer` / `props.actions`
  （详见 [第 6 章](06-列表与集合控件.md)）

### 0.1.70+ 的归一化兜底

基座 0.1.70 起做了「写法归一化」，所以下面这些**也能工作**：

```js
// ① 节点层裸写字段 → 自动并入 props
{ type:'text', text:'Hello', size:18 }              // ✅ 等价于 props:{text,size}

// ② props.children → 自动上提到节点层
{ type:'card', props:{ children:[...] } }           // ✅ 也能渲染

// ③ 脏 props 值被强制纠正
{ type:'text', props:'oops' }                       // props 被重置为 {}，不崩
```

但**别依赖这个**：

1. 它是兼容层，不是让你随便写；
2. `list` 的 `children` 就算被归一化也依然**不读**（ListNode 设计上就没有 children）；
3. 规范写法才能在 [第 13 章](13-调试与自检.md) 的校验器下保持干净。

**结论：按规范写 —— props 里放字段，children 与 props 平级。**

## 3.3 渲染模式：state → render

界面是**声明式**的：你描述「现在应该是什么样」，基座负责画。

```js
// ---------- 1. 状态 ----------
const state = { count: 0, name: '' };

// ---------- 2. 渲染函数：状态 → 树 ----------
function render() {
  $ui.render({
    type: 'root',
    props: { title: '计数器' },
    children: [
      { type: 'text', props: { text: '当前: ' + state.count, size: 20, bold: true } },
      { type: 'input', id: 'name', props: { value: state.name, placeholder: '名字', onChange: 'name' } },
      { type: 'row', props: { gap: 8 }, children: [
        { type: 'button', id: 'inc', props: { text: '+1', onClick: 'inc' } },
        { type: 'button', id: 'reset', props: { text: '清零', onClick: 'reset', variant: 'outlined' } },
      ]},
    ],
  });
}

// ---------- 3. 事件：改状态 → 重渲染 ----------
$ui.on('inc',   () => { state.count++; render(); });
$ui.on('reset', () => { state.count = 0; render(); });
$ui.on('name',  (e) => { state.name = e.value; render(); });

$app.on('launch', render);
```

**关键点：**

- **每个交互都走同一循环**：事件 → 改 state → `render()`
- **值控件必须受控**：`input` 的 `value: state.name` 要与 state 同步，
  否则输入框不显示你键入的内容
- **改完 state 一定要 render()**，否则 UI 与真实状态不一致（「开关回弹」的根因）
- `render()` 里别做耗时操作（网络请求），异步回来后再调一次

## 3.4 事件机制

### 节点挂事件名，全局注册处理函数

```js
// 节点上：onClick / onChange / onSubmit / onLongClick / onTabSelected / more / onEndReached / onRefresh
{ type: 'switch', id: 'sw', props: { label: '启用代理', checked: true, onChange: 'switched' } }

// 全局（注册一次即可，页面栈变化后旧闭包可能过期，所以用字符串名而非闭包）
$ui.on('switched', (e) => {
  // e = { id: 'sw', value: true, ... }
});
```

### payload 里有什么

| 字段 | 何时有 | 说明 |
|---|---|---|
| `e.id` | 总是 | 触发节点的 `id`。**用 `e.id` 回查数据，不要闭包捕获索引** |
| `e.value` | 值控件 `onChange` | string / number / boolean，看控件 |
| `e.selected` | `chip` 的 `onClick` | 是否变为选中态 |
| `e.index` / `e.prev` | `tabs` 的 `onTabSelected` | 新/旧页签下标 |

### 按 id 回查数据（推荐写法）

```js
const state = { files: [/* {id:'f1', name:'a.mp4'} */] };

// ✅ 从当前 state 回查，数据永远最新
$ui.on('play', (e) => {
  const f = state.files.find(x => x.id === e.id);
  if (f) play(f);
});

// ❌ 渲染时闭包捕获索引：列表刷新后 index 指向别的数据了
items.forEach((it, i) => { /* ...onClick: 这里没法直接用闭包... */ });
```

### 事件名可以复用

多个节点用同一个事件名，handler 里用 `e.id` 区分：

```js
$ui.on('itemClick', (e) => console.log('点了', e.id));
```

## 3.5 root：屏幕容器

每个页面（`render`/`push` 的对象）通常以 `root` 开头：

```js
{
  type: 'root',
  props: {
    title: '页面标题',      // 顶栏标题
    subtitle: '副标题',     // 可选
    scroll: true,           // true = 整页可滚动；⚠️ 不能与 list/grid/tabs 混用
    id: 'page-home',        // 可选，用于滚动位置记忆（见 10.4）
  },
  children: [ /* ... */ ],
}
```

**`scroll` 的规则（重要）：**

| 场景 | 写法 |
|---|---|
| 内容少，一屏放得下，想上下滑 | `scroll: true` |
| 有长列表 | `scroll: false`（默认），里面放 `list`/`grid` |
| `list`/`grid`/`tabs` | **绝对不能**放进 `scroll:true` 的 root |

> `list`/`grid`/`tabs` 是 **Lazy 组件**（自己管滚动与回收）。
> 放进 `verticalScroll` 会被给「无限高度约束」导致崩溃。
> 基座 0.1.42+ 有自动降级防护，但**别指望它，自己写对**。

## 3.6 常用容器组合套路

### 套路 1：设置页（分组卡片）

```js
{
  type:'root', props:{title:'设置', scroll:true},
  children:[
    { type:'text', props:{text:'━ 网络 ━', size:13, color:'#4FC3F7', bold:true} },
    { type:'card', children:[
      { type:'input', id:'srv', props:{value:state.srv, placeholder:'服务器地址', onChange:'srv'} },
      { type:'switch', id:'sw', props:{label:'启用代理', checked:state.on, onChange:'sw'} },
    ]},
    { type:'text', props:{text:'━ 关于 ━', size:13, color:'#4FC3F7', bold:true} },
    { type:'card', children:[
      { type:'text', props:{text:'版本 1.0.0', size:12, color:'#888'} },
    ]},
  ],
}
```

### 套路 2：列表 + 底部固定操作栏

```js
{
  type:'root', props:{title:'文件'},
  children:[
    { type:'list', props:{
        items: state.files,
        footer: [                                   // ⚠️ footer 是 props 里的，不是 children！
          { type:'actions', props:{ align:'fill', items:[
            { text:'删除', onClick:'del' },
            { text:'重命名', onClick:'ren' },
          ]}},
        ],
    }},
  ],
}
```

### 套路 3：表单（竖排输入）

```js
{
  type:'root', props:{title:'登录', scroll:true},
  children:[
    { type:'card', children:[
      { type:'column', props:{gap:10}, children:[
        { type:'input', id:'u', props:{placeholder:'用户名', value:state.u, onChange:'in'} },
        { type:'input', id:'p', props:{placeholder:'密码', type:'password', value:state.p, onChange:'in'} },
        { type:'button', id:'go', props:{text:'登录', onClick:'login'} },
      ]},
    ]},
  ],
}
```

## 3.7 未知控件会怎样

写了基座不认识的 `type` → **渲染一张红色兜底卡片**（显示 type 名），**不会崩溃**。
这是有意的向后兼容设计：旧基座跑新应用不至于闪退。

但如果你在自己手机上看到红卡片，说明 `type` 拼错了 —— 去
[第 4 章](04-控件速查表.md) 核对拼写。

## 3.8 调试小技巧

基座应用页顶栏右侧有 **🛠 调试器** 按钮，弹出 Console 面板，能看到：

- `console.log` 输出
- **UI 契约校验告警**（0.1.64+，写了不生效的字段会 warn）
- 应用 error

所以**养成在关键路径 `console.log` 的习惯**，比盲猜快得多。详见
[第 13 章](13-调试与自检.md)。
