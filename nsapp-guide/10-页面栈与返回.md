# 第 10 章 · 页面栈与返回

**这一章是「多层界面返回错乱」的唯一解药。** 基座对页面栈有明确分工：
**UI 栈归基座管，业务栈归你管，两边不要互相伸手。**

---

## 10.1 三个方法的语义

| 方法 | 作用 | UI 栈 | 什么时候用 |
|---|---|---|---|
| `$ui.render(tree)` | 替换当前层 | 不变 | 刷新当前页内容（列表更新/设置回显/状态切换） |
| `$ui.push(tree)` | 压入新屏 | **+1** | 进入新页面（目录/详情/设置） |
| `$ui.pop()` | 返回上一屏 | **-1** | 仅用于 push 出来的子页的「返回」按钮 |
| `$ui.popToRoot()` | 一路回根 | 归零 | 极少用 |

```js
// ✅ 进目录 = push
$ui.push({ type:'root', props:{ title: dir.name }, children:[ {type:'loading'} ] });

// ✅ 同页数据刷新 = render
$ui.render({ type:'root', props:{ title:'列表' }, children:[ {type:'list', ...} ] });
```

### ❌ 反面教材

```js
// 进多层目录也用 render —— UI 栈永远只有 1 层，
// 返回键一按就直接退到首页/退出应用
// （某个云盘应用 0.1.11 之前的实际 bug）
$ui.render({ type:'root', props:{ title: dir.name }, ... });
```

---

## 10.2 铁律 1：进新页面必须 push

判断标准很简单：

| 场景 | 用 |
|---|---|
| 用户点进去看详情 | `push` |
| 打开设置页 | `push` |
| 同一页内 tab 切换 | `render`（或基座自己切） |
| 列表刷新/加载更多 | `render` |
| 输入框内容变化 | `render` |
| 从 A 目录进 B 目录 | `push`（每层一级，返回键逐层退） |

## 10.3 铁律 2/3：返回键与 back 事件

### 返回键处理链

```
用户按返回
  → 全屏中？ → 退全屏
  → 播放中？ → 先关视频
  → 应用页？  → 先问 $ui.setBackHandler（返回 true=已消费，false=放行）
             → 基座 pop UI 栈
             → 发 appBack RPC → 触发 $app.on('back')
```

### `$app.on('back')` 只同步业务状态

```js
// ✅ 正确：只同步自己的业务栈，不碰 UI
$app.on('back', () => {
  if (pathStack.length > 1) pathStack.pop();    // 自管业务面包屑
  syncStateToTop();                             // 把状态同步到新的栈顶
});

// ❌ 错误：在 back 里调 $ui.pop / $ui.render
//   UI 栈基座已经 pop 了，你再 pop 会把上一层也弹掉
//   → 「返回直接回主页」「返回栈错乱」
```

### 应用内模态状态用 `$ui.setBackHandler`

多选模式、浮层、抽屉打开时，让返回键先关它们：

```js
$ui.setBackHandler(() => {
  if (state.selectMode) { state.selectMode = false; render(); return true; }   // 已消费
  if (state.drawerOpen) { state.drawerOpen = false; render(); return true; }
  return false;   // 放行 → 基座正常逐层 pop
});
```

**要求**：
- fn **必须同步返回布尔**，禁止在其中 `await`
- 未注册 / 返回 false / 抛异常 / 600ms 超时 → 基座走默认逐层 pop
- 用 `$ui.clearBackHandler()` 清除

> 这替代了早期的「push 占位层让返回键触发 appBack」hack。别再那么写。

### 子页的「返回」按钮

```js
function detailPage(item) {
  return { type:'root', props:{ title:'详情', id:'detail-'+item.id }, children:[
    { type:'text', props:{ text: item.name, size:16, bold:true } },
    { type:'button', props:{ text:'← 返回', variant:'text', onClick:'goBack' } },
  ]};
}

$ui.on('goBack', () => $ui.pop());   // push 出来的子页才允许 pop
```

## 10.4 铁律 4/4b：不重建页面、不自己管滚动

### 滚动位置基座全权负责（0.1.63r20+）

基座按「应用 + 页面标识 + 容器序号」记忆每个滚动容器的位置，
「下滑到第 20 项 → 点进详情 → 返回」**自动回到第 20 项**。

```js
// ✅ 应用什么都不用做
// ❌ 不要自己写: $prefs 存 firstVisibleIndex、render 后手动滚动等
```

两条相关约定：

1. **页面标识优先取 `root` 的 `id`**。想让「结构相似的不同页面」各自记忆位置，
   给 root 加稳定 id：
   ```js
   { type:'root', props:{ title:'详情', id:'detail-'+docId }, children:[...] }
   ```
2. **退出应用即清空记忆** —— 重新进入应用从顶部开始。

### 返回后不要重建整页

```js
// ❌ 错误: 用 render 重建整棵页面结构去"恢复"上一页
$app.on('back', () => { renderFullPageFromScratch(); });

// ✅ 正确: 返回后的页面内容由基座保留原 UI 栈帧，
//    应用只在 back 里同步数据，需要刷新时再 render 当前栈顶
$app.on('back', () => { pathStack.pop(); if (needRefresh) render(); });
```

## 10.5 铁律 4c：`onEndReached` 必须自己判有没有下一页

**基座只负责「滚到底了，通知你」，它不知道你的数据是否翻完。**

```js
// ❌ 错误: hasMore 算出来了却没用
$ui.on('more', () => loadPage(false));
async function loadPage(fresh) {
  const list = await fetchPage(dir);        // 伪代码: 真实请求见 11.4
  dir.hasMore = list.length === PAGE_SIZE;   // 算了不用
  renderPage();                              // 无条件渲染
}
```

后果链：滑到最后一批 → 仍请求一次 → 返回 0 条 → 数据没变 → 照样 `renderPage()`
→ 基座整页重建 → 滚动位置归零 → 用户看到「**一滑到底就跳回顶部**」。
（某个云盘应用 的真实 bug，两个应用同款。）

```js
// ✅ 正确
$ui.on('more', () => loadPage(false));

async function loadPage(fresh) {
  const c = top();
  if (!fresh && c.loaded && !c.hasMore) return;   // 已加载过 且 没有下一页 → 什么都不做
  c.loading = true; renderPage();
  const list = await fetch(c.offset);
  c.hasMore = list.length === PAGE_SIZE;          // 满一页 = 可能还有
  c.loaded  = true;                               // 标记已加载过
  c.items   = fresh ? list : c.items.concat(list);
  c.loading = false; renderPage();
}
```

**要点：**

- 用 **`loaded` + `hasMore`** 两个标记判，不要用 `items.length > 0` 这类间接信号
  （空目录 / 首屏未加载会误判）
- `fresh = true`（进新目录 / 刷新 / 点重试）**必须放行**，那不是翻页
- 为什么不能靠基座兜底：基座恢复滚动位置时会把「首个可见项」一下跳到末尾，
  **瞬间满足到底条件** →「恢复 → 应用翻页 → replace 重建 → 又恢复」抖动。
  基座有 300ms 恢复抑制窗口（0.1.63r22），但**根治必须在应用侧**。

## 10.6 多页面应用的标准结构

```js
// ---------- 业务栈（你自己管） ----------
const pathStack = [{ name:'首页', data:null }];
function top() { return pathStack[pathStack.length - 1]; }

// ---------- UI 渲染（跟着业务栈走） ----------
function renderApp() {
  const t = top();
  if (t.name === '首页') renderHome();
  else if (t.name === '目录') renderDir(t.data);
  else if (t.name === '详情') renderDetail(t.data);
}

// ---------- 返回：只同步业务栈，不碰 UI 栈 ----------
$app.on('back', () => {
  if (pathStack.length > 1) {
    pathStack.pop();
    renderApp();               // 刷新当前栈顶内容（基座已 pop 了 UI 栈）
  }
});

// ---------- 进入子页：push UI 栈 + 压业务栈 ----------
$ui.on('openDir', (e) => {
  const dir = findDir(e.id);
  pathStack.push({ name:'目录', data:dir });
  $ui.push({ type:'root', props:{ title:dir.name, id:'dir-'+dir.id }, children:[
    { type:'loading', props:{ text:'加载中…' } },
  ]});
  loadDir(dir).then(renderApp);
});
```

## 10.7 自检清单

写完多页应用，逐条对：

- [ ] 进新页面用的是 `$ui.push`，不是 `render`
- [ ] 没有在 `$app.on('back')` 里调 `$ui.pop()` / `$ui.render()` 去「恢复」页面
- [ ] 多选/浮层用 `$ui.setBackHandler` 消费返回键，且 fn 同步返回布尔
- [ ] `onEndReached` 里有 `if (!fresh && loaded && !hasMore) return;`
- [ ] 没自己存/恢复滚动位置
- [ ] 结构相似的多个页面给 root 加了稳定 `id`
- [ ] `list`/`grid`/`tabs` 没放进 `root scroll:true`
- [ ] `list` 的 `actions`/`header`/`footer` 写在 `props` 里，不是 `children`
